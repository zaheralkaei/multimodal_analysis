# Code audit — October 2026

Scope: every script in `scripts/`, plus the two committed dashboards in `reports/`.
Method: line-by-line read, then an end-to-end run on a synthetic 20 s video
(4 solid-colour shots of 5 s each: red, green, blue and a test pattern) so that
each shot's thumbnail could be checked against a known colour.

## TL;DR

The earlier audits (`AUDIT.md`, `AUDIT_R2.md`) checked that the outputs were
**consistent with each other**, e.g. caption vs emotion vs lighting. They did not
check that the outputs **describe the right shot**. They don't: with the default
2 fps extraction, every per-shot vision result and camera-motion result in the
committed dashboards comes from the wrong part of the video.

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | **Critical** | Phases 1 and 3 assume frames were extracted at 1 fps. At the default 2 fps, each shot's mid-frame and its optical-flow frames come from about **half the shot's timestamp**. | Fixed |
| 2 | **Critical** | `run_pipeline.py` can analyse the **wrong video**. Phase 0 always downloads to `data/raw/video.mp4` (yt-dlp skips the download if that file exists), and phase 1 falls back to that file for local sources. | Fixed |
| 3 | High | Phase 6 crashes on current librosa + NumPy 2 (`float()` on a 1-element tempo array). `requirements.txt` allows these versions. | Fixed |

| 5 | Medium | `run_pipeline.py` builds shell strings (`shell=True`) from the URL, path and model. A source containing `"` or `$(…)` breaks the command or injects into it. | Fixed (argument lists) |

| 7 | Medium | "Cut on beat" counts t = 0 (the first shot) as a cut, and has no chance baseline. At ~2 beats/s with ±100 ms tolerance, random cuts land "on beat" about 40% of the time. | Fixed: first shot excluded; `cuts_on_beat_chance_pct` added |

### Evidence for #1 (from the committed dashboards)

| Video | Shot | Shot time | Thumbnail used | That frame's time at 2 fps |
|---|---|---|---|---|
| `rtwpk9rb1Dc` | 70 | 208.2–213.1 s | `frame_00211` | 105.0 s |
| `rtwpk9rb1Dc` | 1 | 2.8–5.2 s | `frame_00005` | 2.0 s (previous shot) |
| `Z2ki180nHCI` | 32 | 121.2–125.6 s | `frame_00124` | 61.5 s |

The same mapping drives phase 3. Its frame range `int(start)+1 … int(end)+1` also
includes one frame past the shot end. So `shot_vision.csv`, `shot_camera.csv`,
`sync_per_shot.csv` and both `reports/*/dashboard.html` are invalid and must be
regenerated (phases 1→8). Phase 2's resume logic now discards the old rows
automatically, because their `mid_frame` no longer matches. Conclusions in
`docs/COMPARISON_1FPS_VS_2FPS.md` (the 2 fps camera-motion distribution) were
computed on misaligned frames and should be redone.

On the synthetic video, the fixed code picks mid-frames `00006/00016/00026/00036`
(red/green/blue/test pattern, all correct). The old formula would have given
`00003/00008/00013/00018`, and the last two are green, not blue or the test pattern.

## Follow-up: improvements implemented

The recommendations from the first pass have all been implemented. Building
and testing them turned up more bugs (marked **bug**).

### Bugs found while implementing

| Severity | Finding | Fix |
|---|---|---|
| **High** | Camera directions were **inverted**: content flowing right was labelled `pan-right` (it is a pan *left*), and outward flow was labelled `zoom-out` (it is a zoom *in*). | Phase 3 rewritten; directions verified on synthetic clips with known motion |
| Medium | The dashboard's shots and lyrics timelines drew bars vertically, so they did not tile the time axis. Present since round 1. | Horizontal bars with `base` = start time |
| Medium | `_normalize_emotion.py` failed its own built-in self-test (model commentary containing "downcast" became `sad`). `wistful` was listed under two emotions. | Whole-word matching, no guessing on long text, duplicates removed; now under pytest |
| Medium | A circular-shift permutation test for cut-on-beat has almost no power, because beat grids are near-periodic (p = 0.22 for perfectly on-beat cuts). | Each cut is shifted independently within ±½ of its local beat period (p = 0.0002; false-positive rate 2.5% at α = 0.05) |
| Medium | With 8 shots, the bootstrap called a meaningless correlation significant. | No CI or significance claims below 20 shots |
| Low | Phase-skip logic ignored code changes. | Each phase records sha1 hashes of the modules it imported |
| Low | `shot_detection_stats.json` showed `detector: adaptive` because a parameter overwrote the descriptive name. | Fixed key order |
| Low | Embedded thumbnails with `loading=lazy` did not load; long words caused sideways scrolling on phones. | Removed lazy loading; wrapping and scroll containers |

### Implemented

**Structure and provenance**
- `scripts/common.py`: single source for paths, frame timing, tag
  vocabularies and camera labels (previously copied into each phase).
- Every phase writes `run_info.json` entries: argv, parameters, git commit,
  code hashes, input/output fingerprints. `run_pipeline.py` skips phases that
  are up to date (`--force` to override); `--skip 2,4,5`.

**Methodology**
- Phase 1: AdaptiveDetector by default (more robust to fast motion and
  flashes), plus fade-to-black detection; three key frames per shot. The
  docstring no longer claims dissolve detection.
- Phase 2: three frames per shot; JSON schema with `enum` for camera and
  emotion, falling back to JSON mode plus normalisation if the endpoint
  rejects schemas (the cloud API was found not to enforce `format`); 4
  parallel requests; model recorded; failed rows retried on resume.
- Phase 3: feature tracking + RANSAC similarity transform, so independently
  moving subjects are outliers. Speeds are normalised to frame size per
  second, there are per-class thresholds (all CLI flags), a shake/handheld
  rule, and a still-frame fallback for textureless shots.
- Phase 4: word timestamps; `--separate-vocals` runs Demucs first.
- Phase 5: softmax per tag group (mood / section / instrument); batched; `--device` honoured.
- Phase 6: features computed once and averaged per second; onset strength added.
- Phase 7: cut-on-beat at ±50/100/200 ms with chance level and permutation
  p-values; Spearman correlations with moving-block bootstrap CIs, answered as
  plain-language questions; audio values weighted by overlap with each shot.

**Validation and comparison**
- `label_shots.py` produces a blind labelling page (key frames and dropdowns; answers saved
  in the browser; exports CSV). `validate_labels.py` reports accuracy with
  Wilson CIs and Cohen's kappa, including camera-family and emotion-valence
  levels. The dashboard shows the result, or a warning when labels are unvalidated.
- `compare_videos.py`: side-by-side report across videos, flagging
  differences in detector, fps, vision model or code version.

**Engineering**
- 67 pytest tests on synthetic media with exact ground truth, including a
  fake Ollama server for phase 2 and an end-to-end pipeline run. GitHub
  Actions runs ruff and pytest on Python 3.12 and 3.13.
- `requirements.txt` capped at next majors, `requirements-ci.txt` pinned,
  `pyproject.toml`. Unused `pandas` removed.
- Dashboard: self-contained (base64 thumbnails), working filters and
  lightbox, provenance table, `--offline`, mobile layout checked at 390 px.
- `experiments/`: the Windows-only test scripts made portable and documented.
- ffmpeg timeouts scale with video length.
